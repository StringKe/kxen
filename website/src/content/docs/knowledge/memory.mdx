Memory 保存从历史 Session 和长期工作中提炼出的稳定信息。它用于在新任务中恢复相关事实，不用于重放完整对话。

## 来源

Memory 可以来自:

- Agent 主动通过 knowledge 工具沉淀。
- 用户在删除 Session 时明确选择「删除并沉淀个人知识」。
- 用户在个人设置中明确开启的后台 consolidation。
- 用户维护的长期条目。

自动知识沉淀默认关闭，只读取个人配置，并且只写个人 scope。启用后，每 30 分钟扫描近 24 小时的活跃 Session，把各自最近 20 条文本和注入上下文发送给该 Session 显式选择的模型，未显式选择时使用其 Workspace 的 `chat` 角色路由。路由、MRM 限额和 Circuit 始终来自 Session 所属 Workspace，不会因前台切换 Workspace 而改变。删除 Session 默认直接删除；选择沉淀时，界面会显示本次目标 Provider，Provider 处理失败会保留 Session 并显示错误，不会静默删除。自动沉淀不能把失败输出写成事实，也不能静默覆盖项目 Rules。

## 检索

Memory 与 Notes 一起参与检索:

1. 使用涉及文件和描述生成查询。
2. 使用 BM25 进行文本相关性排序。
3. 配置 embedding 后加入语义召回。
4. 对项目 scope、较新条目和冲突版本调整权重。
5. 对同 slug 结果去重并截取最相关条目。

没有涉及文件时，系统回退到最近日期的 3 条内容。单条注入正文最多使用 500 个字符，避免长期知识无限占用上下文。

## 冲突处理

内容高度相似但事实不同的条目会被视为潜在冲突，较旧版本降低权重。项目条目优先于个人条目，但 Memory 仍不能覆盖 Safety 和激活的项目 Rules。

## Scope

项目 Memory 位于 `file:///path/to/workspace/.agents/memory/`。个人 Memory 位于 `file:///Users/you/.agents/memory/`。

项目 Memory 应只保存团队长期需要的事实。Agent 通过 knowledge 工具写项目 scope 前必须显示 description 和 content 预览并获得 Approval；没有 Approval channel 时失败关闭。个人偏好、个人工具习惯和跨项目经验保存在个人 scope。

## 与 Session 的区别

Session 是完整执行历史。Memory 是从历史中选出的稳定知识。直接删除 Session 不会自动生成 Memory；只有明确选择「删除并沉淀个人知识」才执行一次蒸馏，因此重要信息应显式沉淀。
